《像素日记》微信小程序产品设计说明书（完整版）
一、 项目概述
1.1 产品定位
“像素日记”是一款面向年轻群体的轻量级情绪记录与陌生人共鸣小程序。通过极简的“点选表情→日历染色”动作完成每日打卡，并辅以“年度像素画布”生成与“匿名情绪弹幕广场”，帮助用户在无需长篇大论的前提下，记录生活、自我洞察、并在匿名环境中获得情绪共鸣与治愈。

1.2 目标用户
喜欢极简记录、不想写长篇日记的年轻人；

有情绪记录习惯，渴望自我觉察的用户；

追求治愈、轻社交体验，希望看到他人相似的喜怒哀乐的人群。

二、 核心功能模块设计
2.1 日常情绪打卡（核心操作）
打卡入口：用户点击主页日历中“当天”未打卡的格子，或点击右下角浮动“+”按钮。

交互流程（弹窗式，Bottom Sheet）：

第一步（情绪必选）：弹出6种像素风格情绪表情（😊快乐、😌平静、😥难过、😰焦虑、😴疲惫、🎉惊喜）。用户必须点选1种，点击伴随手机震动反馈（wx.vibrateShort）。日历格子立即变色。

第二步（文字选填）：底部自动弹起输入框，提示“今天有什么想倾诉的吗？（选填）”。

第三步（隐私设置）：输入框右下角附有开关按钮“🔘 匿名发布到广场”，默认关闭。

保存：点击底部“✓ 记录今天”大按钮，弹窗顺滑收起，打卡完成。

补录机制：允许用户点击过去未打卡的空白格子进行补录，补录记录以色块边缘带虚线阴影作为区分。

2.2 日历全景视图
顶部导航：显示当前月份（如“2026年7月”），左右箭头可切换月份。

日历网格（CSS Grid/Flex）：7列 * 6行的像素风格网格。

未打卡：浅灰色背景，带微弱像素点占位。

已打卡：完全填充对应的莫兰迪色系情绪颜色。

今日高亮：当日格子带有动态发光呼吸边框，引导点击。

交互：长按已打卡格子弹窗，可修改当日情绪；轻点查看当日详情。

2.3 年度情绪画布生成（出圈亮点）
入口：位于“我的”个人中心底部。

生成逻辑：用户点击“🖼️ 生成年度像素海报”，系统拉取该用户过去一整年的所有情绪记录（365天）。

视觉输出：使用微信 Canvas API 在本地绘制一张 1080x1080 的高清像素风海报。海报自带年份、用户昵称，以及一句根据年度情绪占比生成的总结文案（如：“2026年，你的主色调是‘平静’，感谢安稳的每一天”）。

分享：调用 wx.saveImageToPhotosAlbum 允许保存至相册，用于朋友圈分享拉新。

2.4 情绪数据统计与洞察
月度情绪彩虹：在月度视图下方，提供极简的条形图或饼图，展示当月情绪分布。

战绩徽章：展示“连续打卡天数（连胜）”，达到7天、30天、100天解锁专属文字勋章。

年度情绪词库：系统自动判定出现频率最高的情绪，给予用户趣味称号（如“快乐小神仙”）。

2.5 情绪共鸣广场（轻社交）
今日情绪气象：顶部展示今日全平台情绪占比，如“今日共有 632 人打卡，54% 感到快乐”。

匿名弹幕墙：

数据源：仅从数据库中拉取设置了 is_public: true 且包含文字的内容。

交互：彩色气泡从屏幕右侧向左侧横向飘动（CSS 横向位移动画 translateX）。

抱抱互动：每条弹幕下方有一个“🤗 抱抱”按钮，点击数字+1（前端缓存计数，批量合并请求，降低云读写压力）。

2.6 用户中心与设置
基础信息：自动读取微信头像、微信昵称。

隐私控制：提供“注销账户/清除所有数据”的入口（设计详见安全部分）。

个性化设置：提供两套默认的“情绪色板”（如：马卡龙色系、赛博霓虹色系），满足用户审美。

三、 技术架构选型
核心原则：纯前端 + 完全免后端服务器。

开发框架：微信原生小程序（WXML/WXSS/JS）。（注：如熟悉 Vue，亦可采用 Uni-app 框架打包成小程序，但建议原生以方便直接调用微信云开发接口）。

后端服务：微信云开发（WeChat Cloud Development），涵盖云数据库、云函数、云存储。

渲染工具：

日历网格：CSS Flex / Grid 布局。

弹幕动画：纯 CSS3 @keyframes 动画。

图片生成：微信 Canvas API 2D。

四、 数据结构与云开发模型
仅需在微信云开发控制台建立 2 个数据库集合：

4.1 集合一：user_emotions（个人打卡记录）
字段名	数据类型	必填	备注说明
_id	String	是	系统自动生成
openid	String	是	用户唯一标识（由云函数自动获取，前端禁止传输此字段）
date_str	String	是	格式 YYYY-MM-DD，用作快速按月查询
emotion_code	Number	是	1-6，对应6种情绪颜色
comment_text	String	否	用户今天写的心情文字
is_public	Boolean	否	默认 false，是否允许展示在广场
4.2 集合二：square_messages（广场弹幕缓存，含防泄密设计）
字段名	数据类型	必填	备注说明
_id	String	是	系统自动生成
text	String	是	弹幕内容
emotion_code	Number	是	仅用于赋予弹幕气泡对应的情绪颜色
created_at	Date	是	创建时间（用于广场时间排序）
hug_count	Number	否	抱抱数量（默认0）
注意			此表严禁包含 openid 或任何用户隐私标识
五、 安全性与隐私保护完整设计（必须严格执行）
为了确保小程序能顺利通过微信官方审核，并合法合规运营，必须执行以下安全配置：

5.1 数据传输安全
策略：所有向云数据库的交互均通过微信云函数（Node.js）进行，必须关闭前端直接访问数据库的权限。

实现：数据库权限设为 “所有用户不可读，不可写”。云函数调用时，接口强制通过 wx-server-sdk 下的 getWXContext().OPENID 获取用户真实身份，严禁前端传递任何 openid 参数，彻底杜绝伪造身份和篡改他人数据的可能。

5.2 内容安全合规（防止封号风险）
策略：情绪广场属于 UGC 模式，必须强制接入微信官方的文本和图片安全接口。

实现：

在发布弹幕的云函数中，使用 security.msgSecCheck 对用户输入的 comment_text 进行检测。如命中敏感词（涉及政治、暴恐、色情等），云函数直接拦截写入数据库，返回错误提示给前端。

若后续开发支持图片发布，则必须接入 security.imgSecCheck 进行图片过滤。

5.3 用户隐私保护（法律合规）
隐私协议弹窗：小程序首次启动时，必须调用 《微信小程序隐私保护指引》 弹窗，明确告知用户收集的内容（微信头像、昵称、情绪数据、文字内容）及用途（记录、生成海报、广场展示），待用户勾选同意后才允许使用。

数据库敏感字段剔除：在 square_messages（广场弹幕）数据库中，绝对严禁存储 openid、IP地址或用户昵称，确保广场内容绝对匿名，即使数据库被攻破，也无法溯源到具体个人。

数据删除权（注销）：在“我的”页面设置入口，提供“彻底清除/注销账号”按钮。点击确认后，云函数将执行物理删除（remove()），彻底销毁该 openid 下的所有 user_emotions 及关联数据，满足《个人信息保护法》要求。

六、 UI/UX 视觉规范建议（开发参考）
整体风格：极简主义、治愈系、复古像素风（类似 GameBoy）。

色彩系统：

背景色：奶油白 (#F5F5F7) 或 深邃黑 (#121212)。

情绪色块：采用 6 种低饱和度莫兰迪色系（例如：珊瑚红、鼠尾草绿、静谧蓝、烟灰、香芋紫、姜黄色）。

字体：推荐引入开源的像素风格 Web 字体（如 Zpix），提升整体日历页面的精致感。

动效：点击情绪图标时的弹性回弹、月份切换时的平滑左右滑动、日历格子的渐显上色，均需通过 CSS transition 和 animation 实现，提升解压感。

七、 开发实施路线图（MVP 到 迭代）
为保障能够在2-3周内看到可用的 Demo，建议严格按照以下优先级进行排期：

第一阶段（第 1 周）：核心打卡闭环（原型测试）

搭建微信云开发环境，配置数据库安全规则。

实现日历网格渲染、底部打卡弹窗交互。

开发云函数：实现用户的“情绪选填 + 数据入库”。

完成页面“打卡即变色”的视觉逻辑。

第二阶段（第 2 周）：社区共鸣与合规接入

搭建“情绪广场”界面及 CSS 弹幕滚动动画。

完成弹幕发布云函数：重点接入 security.msgSecCheck 合规检测。

开发“抱抱”互动数据增量逻辑。

第三阶段（第 3 周）：数据沉淀与爆发功能

开发“我的”页面，统计月度情绪数据、连胜天数。

攻克核心技术难点：利用 Canvas API 实现“年度像素海报”本地合成与保存。

植入“一键注销”和“隐私协议”引导弹窗。

提交微信官方审核，正式上线运营。
